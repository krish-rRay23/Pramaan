**Document Version:** `v3.1-evidence`  
**Classification:** Engineering Standard Operating Procedure (SOP)  
**Scope:** AI Media Authenticity, Load/Performance Scalability, Cryptographic Micro-benchmarks, and Security Scans.

## 1. Overview & Evaluation Principles

The PRAMAAN evaluation framework operates under strict empirical integrity:
1. **No Fabricated Benchmarks:** Every reported metric is generated by running real Python code against verifiable datasets or live server execution.
2. **Standard Open-Source Tooling:** Custom unverified benchmarking scripts are replaced with established tools:
   - **Performance:** Locust 2.46.6
   - **AI Evaluation:** DeepfakeBench alignment on public dataset derived from Celeb-DF & FaceForensics++
   - **Security SAST:** Bandit 1.9.4
   - **Dependency Audit:** pip-audit 2.10.1 & CycloneDX SBOM
   - **Statistical Analysis:** scikit-learn & scipy standard formulas
3. **Discipline in Production Claims:** Results are explicitly identified as **prototype environment baselines** on single-node execution, avoiding speculative production sizing.

## 2. AI Media Authenticity Benchmark Methodology

### 2.1 Task & Problem Formulation
- **Objective:** Binary classification of human facial media submitted during KYC onboarding ($y \in \{0, 1\}$).
- **Class 0 (Authentic):** Natural unmanipulated camera portrait.
- **Class 1 (Manipulated / Synthetic):** Face-swapped, synthetic diffusion, or boundary-manipulated image.

### 2.2 Dataset Specifications
- **Name:** Celeb-DF & FaceForensics++ Derivative Benchmark Test Set (`yashduhan/deepfake-detection-small`).
- **Source:** Hugging Face Open Datasets (`https://huggingface.co/datasets/yashduhan/deepfake-detection-small`).
- **License:** Apache-2.0 / Open Access Research.
- **Sample Distribution:** 200 total samples:
  - 100 Authentic Real Faces
  - 100 Manipulated Deepfake Faces
- **Local Cache:** `benchmarks/data/deepfake_eval/` (ensures offline reproducibility without network flakiness).

### 2.3 Evaluation Pipeline & Metrics
The evaluation script (`benchmarks/run_ai_benchmark.py`) runs each image through `evaluate_kyc_media()` in `kyc_authenticity.py`.
- **Primary Metrics Computed:**
  - **ROC-AUC:** Area under the ROC curve using `sklearn.metrics.roc_auc_score`.
  - **Average Precision (AP / PR-AUC):** Area under the Precision-Recall curve using `sklearn.metrics.average_precision_score`.
  - **Equal Error Rate (EER):** The threshold $\tau^*$ where False Positive Rate equals False Negative Rate ($\text{FPR}(\tau^*) = \text{FNR}(\tau^*)$).
  - **Confusion Matrix:** True Negatives, False Positives, False Negatives, True Positives at default threshold $\tau=0.50$ and across a sensitivity sweep $\tau \in [0.10, 0.90]$.
  - **Inference Latency:** Per-frame latency measured with high-resolution monotonic clocks (`time.perf_counter`), reporting mean, median (p50), 95th percentile, and 99th percentile.
  - **Memory Footprint:** Resident Set Size (RSS) measured via `psutil`.

### 2.4 Reproducibility Command
```bash
# Ensure virtual environment is active
.venv/Scripts/python.exe benchmarks/run_ai_benchmark.py
```
Outputs generated:
- `benchmarks/AI_BENCHMARK_RESULTS.json`
- `benchmarks/AI_BENCHMARK_FINAL.md`

## 3. Performance & Scalability Benchmark Methodology

### 3.1 Architecture Under Test
- **Server:** FastAPI application (`main.py`) running with Uvicorn ASGI server.
- **Data Persistence:** Hybrid SQLite3 persistent relational store (`repository.py`) combined with in-memory thread-safe lookup structures (`store.py`).
- **Network Interface:** Local loopback (`127.0.0.1:8009`) eliminating external network noise.

### 3.2 Controlled Load Levels (Locust 2.46.6)
The benchmark runner (`benchmarks/run_performance_benchmark.py`) executes headless Locust tests across three distinct concurrency tiers:

| Tier | Concurrency (Users) | Spawn Rate (users/s) | Run Duration | Realistic Workload Equivalent |
| :--- | :---: | :---: | :---: | :--- |
| **Level 1: Low Concurrency** | 10 | 2/s | 12s | Steady branch traffic during standard business hours |
| **Level 2: Moderate Concurrency** | 50 | 10/s | 15s | Peak midday collection notification dispatch |
| **Level 3: Stress Concurrency** | 100 | 25/s | 18s | Simultaneous batch EMI reminder campaign surge |

### 3.3 Endpoint Flow Composition
The Locust scenario (`benchmarks/locustfile.py`) models real customer and system behavior:
1. `GET /ping` (Health probe)
2. `GET /auth/public-key` (Key discovery)
3. `POST /intent/issue` (LMS capability issuance)
4. `GET /intent/latest/{customer_id}` (Customer app 2.5s shield polling)
5. `POST /intent/verify` (Exact Action Gate cryptographic evaluation)
6. `GET /receipts/customer/{customer_id}` (Customer receipt ledger review)
7. `POST /receipts/verify` (Independent public receipt verification)
8. `End-to-End Composite Journey` (Issue $\rightarrow$ Poll $\rightarrow$ Exact Gate Verify $\rightarrow$ Verify Receipt)

### 3.4 Isolated Cryptographic Primitive Benchmark
To separate raw algorithm throughput from HTTP/network latency, the suite evaluates pure Ed25519 primitives (5,000 iterations):
- `ed25519.Ed25519PrivateKey.generate()`
- `private_key.sign(payload)`
- `public_key.verify(signature, payload)`

### 3.5 Quality Thresholds
- **Error Rate Target:** $\le 1.0\%$ across all load tiers.
- **Latency Target:** 95th percentile latency $\le 600\text{ ms}$ on prototype hardware.

### 3.6 Reproducibility Command
```bash
.venv/Scripts/python.exe benchmarks/run_performance_benchmark.py
```
Outputs generated:
- `benchmarks/PERFORMANCE_RESULTS.json`
- `benchmarks/PERFORMANCE_BENCHMARK_FINAL.md`

## 4. Security Verification & Auditing Methodology

### 4.1 Threat Modeling & Failure Mode Testing
- **Suite:** `test_failure_modes.py`
- **Scope:** 16 critical enterprise attack scenarios including forged signatures, revoked keys, expired TTLs, replayed nonces, modified payment amounts, swapped UPI destinations, and channel-spoof attacks.
- **Verification Rule:** Every attack must fail-closed to `BLOCKED`. Failure never becomes authorization.

### 4.2 Automated SAST & Secret Scanning
- **Tool:** Bandit 1.9.4 (`bandit -r .`)
- **Focus:** Shell injection, hardcoded credentials, unvalidated deserialization, insecure cryptographic algorithms.
- **Artifact:** `security/bandit_report.json`.

### 4.3 Dependency Vulnerability Audit
- **Tool:** pip-audit 2.10.1 (`pip-audit`)
- **Database:** Open Source Vulnerabilities (OSV) / GitHub Security Advisory Database.
- **Artifact:** `security/pip_audit_report.json`.

### 4.4 Software Bill of Materials (SBOM)
- **Tool:** `security/generate_sbom.py`
- **Standard:** CycloneDX v1.4 JSON.
- **Artifact:** `security/sbom.json`.

### 4.5 Reproducibility Commands
```bash
# Run 16 Failure-Mode Tests
.venv/Scripts/python.exe test_failure_modes.py

# Run Automated Security Scanner
.venv/Scripts/python.exe security/security_scanner.py

# Generate CycloneDX SBOM
.venv/Scripts/python.exe security/generate_sbom.py
```
